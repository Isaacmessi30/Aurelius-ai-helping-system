# Aurelius AI Support

Standalone Discord ticket AI support bot using **discord.js**, **DeepSeek**, local Markdown knowledge, slash commands and staff escalation. It does **not** modify the existing Aurelius ticket bot or run Pterodactyl actions.

## Setup (Pterodactyl, Node.js 20+)
1. Create a Discord bot at https://discord.com/developers/applications and enable **Message Content Intent** in Bot settings.
2. Invite with bot and `applications.commands` scopes; provide View Channels, Read Message History, Send Messages, Embed Links.
3. Set the Pterodactyl startup command to `npm install && npm start` (or install dependencies once and use `npm start`).
4. Set environment variables **DISCORD_TOKEN**, **DISCORD_CLIENT_ID**, **DISCORD_GUILD_ID**, **DEEPSEEK_API_KEY** in Pterodactyl's Startup environment or a local `.env` file. `OWNER_ID` is optional. Use `.env.example` for names.
5. Start the server. Commands are registered in the selected guild automatically. Run `/ai channel add` in a ticket channel or `/ai category add` for a ticket category, then `/ai enable`.

**Do not put real API keys/tokens in Git.** Even private repos retain history and can be copied. Use Pterodactyl variables or GitHub Actions Secrets if needed.

## Commands
- `/ai enable`, `/ai disable`, `/ai status`
- `/ai channel add|remove` (add/remove current or selected channel)
- `/ai category add|remove` (designate all channels under a ticket category)
- `/ai staff add|remove` (role authorized to take over and receive escalation mention)
- `/ai logs` (set escalation log channel, optional)
- `/ai escalate` (request staff help; available to customers in configured ticket channels)
- `/ai reset` (clear cached conversation for current channel)
- `/ai model` (choose `deepseek-flash` or `deepseek-v4-pro`)
- `/ai knowledge` (reload markdown knowledge after editing files)

Admin configuration commands require Manage Guild permission or configured OWNER_ID. Discord permissions are checked server-side.

## Behavior
AI only answers in channels explicitly enabled or inside configured categories. Excludes bots, ignores messages by staff, limits request frequency and monthly usage, truncates messages and sends an escalation when the model cannot help. It uses the last 12 messages per ticket in memory; history is lost on restart. No transcript is persisted. Local JSON config is written to `data/config.json`, so keep that folder persistent for restarts. Runtime changes may be overwritten by fresh file deployments.

## Security and limitations
- Treat ticket input and markdown documents as untrusted; policies/system instructions have priority.
- AI answers are generated by an external API. Don't enter passwords, tokens, payment info, or other secrets in tickets.
- Knowledge is simple local Markdown (not semantic retrieval); files are capped to avoid excessive token bills.
- No direct refunds, restarts, database writes or API account actions.
- Monthly quotas are per bot process and reset at restart; use persistent billing enforcement for hard spend limits.
- Knowledge and config changes on one replica don't synchronize with other replicas. Use one running bot instance.
- Review AI advice before letting it make decisions affecting production resources.

## Local development
```bash
cp .env.example .env
npm install
npm run check
npm start
```

DeepSeek API endpoint: https://api.deepseek.com, default model `deepseek-flash`.

## Verification
GitHub Actions runs `npm install` and `npm run check` on pull requests. Live Discord and DeepSeek authentication requires real credentials configured outside Git.

CI also exercises command initialization in `AI_DRY_RUN=true` mode without logging in to Discord or contacting DeepSeek.

Ticket categories automatically include all their child text channels and threads; individual channel registration is optional. If the bot does not reply after a code update, deploy the latest `main` to Pterodactyl and restart.

## Interactive configuration & approvals
Use `/ai setup` for ephemeral configuration with dropdowns for category, staff role, audit channel and model. Customer messages asking for a human notify the staff roles. Ticket-opening embeds with an `Inquiry` field are read from the most recent 100 ticket messages and supplied as customer context.

Optional Pterodactyl support: set `PTERODACTYL_ACTIONS_ENABLED=true`, `PTERODACTYL_URL`, `PTERODACTYL_CLIENT_API_KEY`, and `OWNER_ID`. Customer can request `/ai request server:<short-id> action:<start|stop|restart>` inside a ticket. The configured review channel gets Accept Action, Deny Action and Staff Takeover buttons. Only `OWNER_ID` can act. Only power operations are implemented; there is no autonomous AI write access, and the owner must verify that the ticket requester owns the target server. All actions default disabled. Use a narrowly scoped Client API key, not an administrator Application API key. Approval state persists to `data/approvals.json`.
