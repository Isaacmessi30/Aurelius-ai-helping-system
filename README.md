# Aurelius AI Support

Standalone Discord ticket AI support bot using **discord.js**, **DeepSeek**, local Markdown knowledge, slash commands and staff escalation. It does **not** modify the existing Aurelius ticket bot or run Pterodactyl actions.

## Setup (Pterodactyl, Node.js 20+)
1. Create a Discord bot at https://discord.com/developers/applications and enable **Message Content Intent** in Bot settings.
2. Invite with bot and `applications.commands` scopes; provide View Channels, Read Message History, Send Messages, Embed Links.
3. Set the Pterodactyl startup command to `npm install && npm start` (or install dependencies once and use `npm start`).
4. Set environment variables **DISCORD_TOKEN**, **DISCORD_CLIENT_ID**, **DISCORD_GUILD_ID**, **DEEPSEEK_API_KEY** in Pterodactyl's Startup environment or a local `.env` file. `OWNER_ID` is optional. Use `.env.example` for names.
5. Start the server. Commands are registered in the selected guild automatically. Run `/ai channel add` in a ticket channel or `/ai category add` for a ticket category, then `/ai enable`.

**Do not put real API keys/tokens in Git.** Even private repos retain history and can be copied. Use Pterodactyl variables or GitHub Actions Secrets if needed.

## Commands
- `/ai enable`, `/ai disable`, `/ai status`
- `/ai channel add|remove` (add/remove current or selected channel)
- `/ai category add|remove` (designate all channels under a ticket category)
- `/ai staff add|remove` (role authorized to take over and receive escalation mention)
- `/ai logs` (set escalation log channel, optional)
- `/ai escalate` (request staff help; available to customers in configured ticket channels)
- `/ai reset` (clear cached conversation for current channel)
- `/ai model` (choose `deepseek-flash` or `deepseek-v4-pro`)
- `/ai knowledge` (reload markdown knowledge after editing files)

Admin configuration commands require Manage Guild permission or configured OWNER_ID. Discord permissions are checked server-side.

## Behavior
AI only answers in channels explicitly enabled or inside configured categories. Excludes bots, ignores messages by staff, limits request frequency and monthly usage, truncates messages and sends an escalation when the model cannot help. It uses the last 12 messages per ticket in memory; history is lost on restart. No transcript is persisted. Local JSON config is written to `data/config.json`, so keep that folder persistent for restarts. Runtime changes may be overwritten by fresh file deployments.

## Security and limitations
- Treat ticket input and markdown documents as untrusted; policies/system instructions have priority.
- AI answers are generated by an external API. Don't enter passwords, tokens, payment info, or other secrets in tickets.
- Knowledge is simple local Markdown (not semantic retrieval); files are capped to avoid excessive token bills.
- No direct refunds, restarts, database writes or API account actions.
- Monthly quotas are per bot process and reset at restart; use persistent billing enforcement for hard spend limits.
- Knowledge and config changes on one replica don't synchronize with other replicas. Use one running bot instance.
- Review AI advice before letting it make decisions affecting production resources.

## Local development
```bash
cp .env.example .env
npm install
npm run check
npm start
```

DeepSeek API endpoint: https://api.deepseek.com, default model `deepseek-flash`.

## Verification
GitHub Actions runs `npm install` and `npm run check` on pull requests. Live Discord and DeepSeek authentication requires real credentials configured outside Git.

CI also exercises command initialization in `AI_DRY_RUN=true` mode without logging in to Discord or contacting DeepSeek.

Ticket categories automatically include all their child text channels and threads; individual channel registration is optional. If the bot does not reply after a code update, deploy the latest `main` to Pterodactyl and restart.

## Interactive configuration & approvals
Use `/ai setup` for ephemeral configuration with dropdowns for category, staff role, audit channel and model. Customer messages asking for a human notify the staff roles. Ticket-opening embeds with an `Inquiry` field are read from the most recent 100 ticket messages and supplied as customer context.

Optional Pterodactyl support: set `PTERODACTYL_ACTIONS_ENABLED=true`, `PTERODACTYL_URL`, `PTERODACTYL_CLIENT_API_KEY`, and `OWNER_ID`. Customer can request `/ai request server:<short-id> action:<start|stop|restart>` inside a ticket. The configured review channel gets Accept Action, Deny Action and Staff Takeover buttons. Only `OWNER_ID` can act. Only power operations are implemented; there is no autonomous AI write access, and the owner must verify that the ticket requester owns the target server. All actions default disabled. Use a narrowly scoped Client API key, not an administrator Application API key. Approval state persists to `data/approvals.json`.

Inquiry reader checks up to 500 recent ticket messages and logs whether the inquiry is found. The first reply should address the inquiry directly.

AI messaging accurately describes the optional owner-approved Pterodactyl power workflow. Ordinary chat never executes live server actions.

## Pterodactyl stop behavior
Use `node src/index.js` as the final foreground process in Startup (prefer `exec node src/index.js` when a shell is used). Avoid `npm start` inside nested `bash -c` shells when diagnosing Stop/Kill issues. The bot now handles SIGTERM and SIGINT to close its Discord client. If the panel still requires Kill, verify the Pterodactyl egg sends the stop signal to the running Node process and has a sensible stop timeout.

## Owner update
`/ai update` fetches `main`, backs up and restores `.env`, installs dependencies, checks syntax and optionally restarts its own Pterodactyl server. To restart automatically, configure `AI_BOT_SERVER_ID`, `PTERODACTYL_URL`, and `PTERODACTYL_CLIENT_API_KEY` with appropriate permission. Use `OWNER_ID` to restrict command use. Updates run with repository write access, so protect the GitHub account and review changes before deploying.

Graceful shutdown changes are validated by CI startup and syntax checks; the real Pterodactyl stop signal must be verified on the deployed egg.

## Verified customer action integration (October 2026)
The bot reads the authoritative existing Paymenter AureliusAccounts Discord-to-billing link using `PAYMENTER_API_KEY`. Server ownership is checked against the linked Panel user with `PTERODACTYL_APPLICATION_API_KEY`; the Pterodactyl Client key executes permitted server operations. No user-provided server ID grants access on its own.

Configure private environment variables `PAYMENTER_URL=https://billing.aureliushosting.com`, `PAYMENTER_API_KEY`, `PTERODACTYL_APPLICATION_API_KEY`, `PTERODACTYL_CLIENT_API_KEY`, `PTERODACTYL_URL`, `AI_ACTION_LOG_CHANNEL_ID`, and `OWNER_ID`. **The panel Application key is privileged.** Never paste these keys in Discord or commit them to Git. Keep `PTERODACTYL_ACTIONS_ENABLED=false` until staging/live checks are complete.

Natural-language start/stop/restart flow: user asks, selects a verified server if needed, confirms via button, and the bot logs the request and submits the power signal without owner approval. Supported owner-reviewed actions currently include adding/removing a subuser, changing startup to Bash/default/custom command, editing non-sensitive editable startup variables, and creating/restoring backups. Owner receives Accept Action, Deny Action and Staff Takeover buttons. Owner approval is enforced in code, not decided by the model. Supported read-only checks include server resources, startup/image, allocations, subusers, backups, schedules, Paymenter services/invoices and database configuration. Staff can request `/ai summary`.

**Not yet implemented:** automatic schedule-task construction, automatic ticket deduplication, incident-status integration, automatic knowledge improvement, arbitrary code repair, service extensions or billing changes. Live Paymenter and Pterodactyl API requests require actual credentials and staging verification; CI only checks code initialization and local tests.

All protected mutations also honor `PTERODACTYL_ACTIONS_ENABLED=false` as a fail-closed global safety switch.

## Schedule operations
Owner-approved schedule deletion and enable/disable are now recognized from natural-language requests containing the schedule ID. The AI first confirms the verified server with the customer. Schedule creation currently supports validated cron fields in the backend, but natural-language schedule creation and task editing remain incomplete. No duplicate-ticket system is planned.

Run `/ai health` as an owner or server manager to inspect Paymenter and Pterodactyl API connectivity without revealing credentials. This is a connectivity probe; it does not certify server ownership or perform a live mutation.

## Console diagnostics (staged)
When a customer reports a crash or startup error, the AI verifies account ownership and retrieves a bounded snapshot of Pterodactyl console output over the authenticated WebSocket. Potential credentials are redacted before displaying output. If no error is found, the user may choose **Start for diagnosis**; the bot logs the request, sends a start power signal and retrieves startup output. No file edits or repeated automatic starts are performed. Requires Node 22's WebSocket implementation, enabled live actions for startup, and a configured audit channel. Live end-to-end verification is still required.

## Owner DeepSeek balance and server suggestions
`/ai balance` checks DeepSeek's official balance endpoint and responds ephemerally only to `OWNER_ID`. Server selection accepts exact names/IDs and conservatively suggests likely partial/typo matches; suggestions require Confirm or Deny before the separate action confirmation. Uncertain/ambiguous matches still show the server list.
